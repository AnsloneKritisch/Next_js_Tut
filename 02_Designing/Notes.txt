# Next.js Layouts 

# Why do we need layers ?
Ans - To create a consistent UI across pages and to avoid code duplication.

WDYM bro ????

Lemme explain with an example. Let's say we have a website with a header and footer. We want to display the header and footer on every page. We can create a layout component that contains the header and footer. Then, we can wrap our pages with the layout component. This way, we don't have to repeat the header and footer code on every page.

Now the Question is how do you use layouts in Next.js ?
Ans - You can basically found there is layout.tsx file in the app folder. This file is used to create a layout for your pages. You can create a layout for your pages by creating a layout.tsx file in the app folder.

Code :

import type { Metadata } from "next";
import { Geist, Geist_Mono } from "next/font/google";
import "./globals.css";

const geistSans = Geist({
  variable: "--font-geist-sans",
  subsets: ["latin"],
});

const geistMono = Geist_Mono({
  variable: "--font-geist-mono",
  subsets: ["latin"],
});

export const metadata: Metadata = {
  title: "Create Next App",
  description: "Generated by create next app",
};

export default function RootLayout({
  children,
}: Readonly<{
  children: React.ReactNode;
}>) {
  return (
    <html lang="en">
      <body
        className={`${geistSans.variable} ${geistMono.variable} antialiased`}
      >
        Navbar
        {children}
        Footer
      </body>
    </html>
  );
}

-- {children} is the content of the page.
--- Navbar and Footer are the UI components that are shared across all pages. right now only words are send to all the side 


- **Nested layouts**: create per-section UI (e.g., dashboard sidebar) by adding `layout.tsx` inside nested folders.
- **Grouping routes**: parentheses in folder names (e.g., `(dashboard)`) allow grouping without affecting the URL path.
- **Dynamic routes**: folder names like `[id]` create dynamic pages and can be nested under a layout.

> Note: `page.tsx` defines route content; `layout.tsx` wraps it with persistent UI.

## Example: simple `layout.tsx` pattern
```tsx
export const metadata = { title: 'My App' };

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        {/* common header / nav */}
        {children}
      </body>
    </html>
  );
}
```
